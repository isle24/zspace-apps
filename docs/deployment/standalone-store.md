# 独立商店部署到 NAS

商店是独立 Go 服务和 Web 页面。NAS 客户端直接使用官方 API；NAS 上的这个服务只负责商店，不需要安装或启动客户端。直接访问商店使用自己的管理员账号、SQLite 元数据和目录，不需要 NAS 账号密码。可选的 NAS 管理员身份复用只用于客户端内进入商店，须由部署者明确配置固定 NAS 来源。

部署入口为 [deploy-store-ssh.sh](../../scripts/deploy-store-ssh.sh)。必须明确传入已有的 sshbind 别名、专用部署目录和应用数据根目录。脚本本身的执行包含 NAS 写入和启动服务，应在具体目标目录、端口和行为获得授权后运行。

## 部署前提与检查

本机需要 Bash、Python 3、Go、pnpm、sshbind 和 SSH，以及已经安装的项目依赖。脚本先从 `sshbind list --json` 选择 `usable: true` 的别名，不读取或复制私钥，不接受密码参数，也不修改 SSH 配置。

NAS 需要 Linux amd64 或 arm64、Python 3、findmnt、lsblk，以及当前 SSH 用户可访问的本机 Docker Unix socket（部署前的镜像缓存诊断也需要此权限）。脚本由这个普通用户启动进程，不使用 sudo，不修改系统服务，不设置开机自启。NAS 重启后的自动恢复尚未包含在这个启动方式中。

两个目录必须已经存在、路径规范且全部路径分量没有符号链接，最终目录属于 SSH 用户且权限为 `0700`。首次使用的部署目录必须为空；脚本不会接管已有非空目录。应用数据根可与部署目录相同，也可另选一个已经批准的专用目录。部署和应用数据目录、Docker 镜像缓存均通过现有存储诊断策略检查：拒绝系统盘、eMMC 和不能可靠确认的卷；接受已核验的 SSD/HDD，以及极空间 `ku_fs` 虚拟数据池中的专用数据目录。Docker 缓存需要已确认的非系统 SSD/HDD；不修改 Docker 的存储位置。

先查看帮助，再核对可用服务器：

```bash
bash scripts/deploy-store-ssh.sh --help
sshbind list --json
```

商店服务固定监听 `0.0.0.0:<端口>`，默认端口为 `18435`，拒绝使用官方 `5055`，在写入前及启动前检查端口。安装应用的 Docker 发布 IP 默认显式设为 `0.0.0.0`，访问主机默认使用选中可用别名的 inventory host，确保 LAN 用户打开应用时指向 NAS。发现冲突、已有本商店进程、异常目录标记或身份不一致的 PID 记录时直接停止，不停止或重建任何已有服务。首次配置只允许来自 NAS loopback 的直接连接。

## 具体部署命令

在项目根目录执行。下面的变量需要填写已经确认的 sshbind 别名和已有专用目录；它们不是用户名、密码或密钥。

```bash
store_alias='已确认的可用别名'
store_deploy_dir='/已确认的数据卷/专用商店目录'
store_data_dir='/已确认的数据卷/专用应用数据目录'
bash scripts/deploy-store-ssh.sh \
  --alias "$store_alias" \
  --deploy-root "$store_deploy_dir" \
  --storage-root "$store_data_dir" \
  --port 18435 \
  --engine local \
  --publish-host 0.0.0.0
```

两个根目录允许填写同一个已批准、首次使用时为空的专用 `0700` 目录；此时存储诊断只执行一次。该目录随后保存商店版本、元数据，以及新应用实例的独立子目录。

| 参数 | 默认值和用途 |
| --- | --- |
| `--engine` | `local` 使用 NAS 当前用户的本机 Docker 权限；`disabled` 只启动商店 UI 和 API、禁用安装执行 |
| `--publish-host` | `0.0.0.0`，安装应用端口的发布 IP；可指定 NAS 上的具体 IP，不接受 DNS、CIDR、端口或 URL |
| `--access-host` | 选中可用别名的 inventory host；可明确指定用户访问 NAS 的 DNS 或 IP，不接受通配绑定地址、URL、端口、凭据或 IPv6 zone |
| `--nas-origin` | 默认留空，关闭 NAS 会话交换；可显式配置唯一、规范的裸 NAS HTTP(S) origin，例如 `http://127.0.0.1:5055`。不接受凭据、路径、查询、片段或非规范端口；不修改官方服务 |
| `--public-origin` | 默认留空；为已经配置的受信任反向代理声明一个裸 HTTP(S) 来源，如 `https://store.example`，不包含账号、密码、路径、查询或片段 |

部署不使用 `sshbind` 作为 NAS 上的常驻引擎，也不复制本机 SSH 密钥。地址参数先在本机校验，在 NAS 再校验，随后通过结构化进程参数交给 Go，不拼接为 shell 命令。`run/<版本>.json` 保存发布 IP、访问主机、公共来源及固定 NAS 身份来源；核对已有进程时同时检查实际启动参数与记录是否一致。

脚本完成以下步骤：

1. 批量检查目录所有权、CPU 架构、当前商店进程、端口及本机 Docker 权限。
2. 本地构建 Linux Go 程序和 Web 商店，并运行只读存储诊断；诊断只在本机创建临时元数据，不在 NAS 创建容器或目录。
3. 打包 `store.html` 及其 Vite 依赖，不打包客户端 `index.html` 和客户端入口代码。通过既有 SSH 别名、`BatchMode=yes` 和标准输入传输，校验 SHA-256 后写入全新版本目录。
4. 以 SSH 普通用户启动自己的进程，保留 PID、Linux 进程启动时间、版本和日志；核对新进程 ready 事件与 HTTP health 的实例 ID。

目录结构如下，已有版本和元数据不会被覆盖或删除：

```text
专用商店目录/
  .space-store-deploy.json       # 部署目录的身份记录
  .space-store-deploy.lock       # 同目录并发部署锁
  releases/<时间戳-随机后缀>/
    space-store                 # Linux Go 程序
    release.json
    web/store.html
    web/assets/...
  metadata/store/                # 共享 SQLite 身份、计划、实例、任务
  logs/<版本>.log
  run/<版本>.json                # PID、启动时间、服务身份和地址配置
```

构建产物保存在本机输出的临时目录，部署失败也保留，便于检查。失败的版本目录、日志、元数据和进程同样保留；脚本没有自动删除或清理路径。

## 首次管理员设置与访问

在本机另开终端，用刚才同一个别名建立仅本机可访问的 SSH 转发：

```bash
ssh -o BatchMode=yes -o ConnectTimeout=15 -o ExitOnForwardFailure=yes \
  -N -L 127.0.0.1:18436:127.0.0.1:18435 "$store_alias"
```

在浏览器打开 `http://127.0.0.1:18436/`，人工填写独立商店管理员账号和密码。必须直接使用这个 SSH loopback 转发；首次设置会拒绝带 `Forwarded` 或 `X-Forwarded-For` 的代理请求，即使代理连接来自 loopback。真实凭据不进入部署命令、文件、日志或提交。已有管理员的服务不能通过首次设置再次覆盖管理员；后续正常登录即可。

局域网地址为 `http://访问主机:18435/`，商店根路径直接打开 `store.html`。HTTP LAN 访问没有传输加密；管理员登录和管理操作优先继续使用 SSH loopback 转发。HTTPS 入口需要另外配置和验收：部署时可追加 `--public-origin 'https://store.example'`，显式允许这个浏览器来源。服务不会因请求中的 `X-Forwarded-Proto` 自动信任外部来源；可信代理仍须正确转发 Host，HTTPS 终止和网络访问权限由管理员配置。不要无条件改写所有请求的 Origin。首次设置仍通过直接 SSH loopback 完成。当前脚本不修改 NAS 反向代理、官方远程访问或防火墙，也不宣称 HTTPS 已通过验证。

## 客户端内复用 NAS 管理员登录

部署时明确增加 `--nas-origin 'http://NAS地址:5055'`，其规范来源必须与客户端当前正常登录的 NAS 地址完全一致。这个参数固定服务端身份核验目标，不修改官方服务。未配置时，客户端内仍可独立登录商店。服务端通过官方 `/auth/token` 核验当前会话和 `is_master` 管理员权限，普通账号不能获得商店管理权限。

在 PC 客户端的商店设置中填写已部署的商店地址，核对执行设备及专用存储目录。第一次进入会显示 NAS 来源、商店来源、商店实例和会话复用说明；确认信任后，后续从客户端进入将使用当前 NAS 管理员会话，无需再输入商店密码。更换 NAS、商店地址或实例需要重新核对绑定。独立商店网页保持自己的账号登录。

只有客户端自身正常登录获得的会话用于交换。商店不接收 NAS 密码，NAS 令牌只在有期限的内存会话中保留，不写入 SQLite、日志或 URL；受保护请求会重新核验官方管理员身份。退出或撤销管理员权限后，NAS 来源的商店授权失效。已经开始执行的安装任务仍由服务端独立运行。

开发 H5 的商店请求也可经同源透明代理按原 `/api/store/*` 路径转发。服务端须明确声明该浏览器来源，例如 `--public-origin 'http://127.0.0.1:5173'`；代理不得绕过身份验证或无条件重写 Origin。此来源仅用于当前开发接入，不代表正式 HTTPS/远程部署已验收。正式切换来源后需要重新核对客户端绑定。

客户端中的可选商店服务地址可以填写这个已部署商店的局域网/HTTPS 地址。独立页面继续使用商店密码登录；仅配置 `--nas-origin` 后，客户端内嵌入口才能在用户信任精确 NAS/商店绑定后交换自己的正常 NAS 会话。局域网可访问不代表官方远程入口或外网访问已经配置完成。

## 后续版本与故障检查

运行中的商店会阻止再次部署，包括换端口的重复启动，以及同一 SSH 用户已经启动、使用相同应用数据根的另一套商店。先检查 `run/<版本>.json`、记录中的 PID/启动时间和 `logs/<版本>.log`。脚本不自动停止进程；升级、回退和停止需要另行确认具体进程和操作。确认原进程已经停止后，重新执行同一部署命令会写入新版本目录，并复用 `metadata/store` 中的管理员和实例记录。

Linux 进程已退出但尚未被父进程回收时，`/proc/<PID>/stat` 可以暂时保留 `Z` 状态，而 `exe` 已消失。脚本在记录检查和进程扫描中识别这种已结束状态，保留旧记录和版本，再正常检查端口；存活进程的启动时间、用户、可执行文件及参数不一致时仍然拒绝部署。合成 fixture 已复现并修复原脚本对此状态的误判。真实部署重试时观察到旧 PID 随后从 `/proc` 消失，但当时未取得 `Z` 状态证据，因此不能断言该次拒绝一定由僵尸进程造成。

preflight 失败会显示远端程序定义的安全故障原因，例如“已有商店运行”或“端口占用”。诊断只接受白名单原因和数字 PID/errno，不显示 SSH 完整命令、远端 stdout、shell 启动噪音或未知 stderr 内容。异常路径和工具失败保留具体错误类别，原始宿主内容不进入输出。

不要通过更换部署根绕过原商店的运行检查；对同一应用数据根使用多套独立商店元数据会失去原有实例归属，应作为单独迁移讨论。现有容器、应用目录和媒体目录始终不由本部署脚本接管。

验证时区分这几件事：脚本语法及本地构建通过、商店进程/health 已确认、浏览器首次配置已完成、具体应用实际安装和健康、官方远程入口实际可达。只有对应操作的真实证据才能算该项完成。

## 可选 NAS 管理员身份交换

Go 服务的 `--nas-origin` 和部署脚本同名参数均默认留空。启用时必须由操作者指定唯一规范 origin；例 `--nas-origin 'http://127.0.0.1:5055'`（从商店进程实际可达的地址）。不能在此参数里放 token、设备会话或密码，不能从客户端请求自动开启。HTTPS、客户端信任和真实账号的验收须另行完成。

`GET /api/store/status` 增加 `nasAuth: {enabled, origin, storeId}`。`storeId` 是已有 SQLite 商店实例身份。私有 `POST /api/store/nas-session` 接受 `providerId`（与该 origin 完全相等）、`storeId`、`token`、`deviceId`、`nasId`；拒绝任意目标 URL 和前端角色字段。必须先完成原有 loopback 独立管理员设置。成功仅返回 `sessionId`、`username`、`expiresAt` 和 `authSource: "nas"`，不返回 NAS token。

商店只向固定 NAS 的 `POST /auth/token` 发送表单；HTTP 超时 5 秒、响应上限 64 KiB，不跟随重定向、不使用代理环境变量。只接受规范成功响应和严格管理员 `is_master`，拒绝普通账号、字符串权限、冲突失败标记及重复 JSON 字段。提供者原始响应和错误不进入产品错误或日志。

NAS 会话最多 128 个、有效期 20 分钟，仅存于独立互斥锁保护的内存中，饱和时拒绝新增，不驱逐有效会话。每次受保护读写均重新验证 NAS 身份，失败撤销；过期、注销、重启或 Close 后不可恢复。注销在本地删除并取消会话，无须 NAS 在线，也不等待仍在读取 body、锁或数据库连接的请求。受保护请求在 body、锁、引擎读取和最终提交前复查精确会话；新元数据先暂存于请求上下文事务，最终 Commit 与撤销共用短暂内存锁。撤销后不能提交新任务、计划或状态回写；注销前已经 Commit 的安装任务继续按原服务生命周期执行。NAS 校验和引擎调用均不持有会话内存锁。现有 SQLite 密码会话、schema、应用记录和原管理员密码不变。商店没有新增 NAS 业务代理。

本项源码验证仅使用本地 `httptest` 合成账号/会话。管理员真实字段、正常 NAS 登录、客户端内嵌交换、HTTPS 和真实部署仍须分别验收。
