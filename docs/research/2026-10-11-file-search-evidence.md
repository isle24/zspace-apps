## 常规索引搜索

常规文件名搜索调用 `POST /file_search/file_search`，调用参数包括：

| 字段 | 当前官方调用含义 |
| --- | --- |
| `name` | 搜索输入文本 |
| `file_path` | 当前实际目录路径；无目录范围时为空字符串 |
| `start` / `num` | 服务端分页，当前搜索页面默认 0 / 30 |
| `order_by` | 排序，初始为 0 |
| `ftype` / `is_dir` | 文件类型与目录筛选，未筛选时为空字符串 |
| `min_size` / `max_size` | 大小筛选，初始为 0 |
| `shared_only` | 共享模式使用 1；普通模式有目录范围时为 0，无目录范围时为 2 |
| `show_hidden` | 包装函数加入当前用户的显示隐藏文件选项 |

官方界面消费响应 `data.list`、`data.total`、`data.index_time` 和可选 `data.skip_dir`。每条结果使用实际 `path` 构造身份，`is_dir` 判断目录，`size` 显示文件大小。客户端后续应使用此服务端分页结果，不能将现有“筛选本页名称”当成 NAS 全局搜索。

这些是公开源码的调用证据；当前正常账号的权限、返回结构和实际结果尚未验证。不要对未返回的路径猜测前缀，也不要把用户可见标题作为文件身份。

# 真实响应中的名称高亮标记（2026-10-11 补充）

正常新客户端登录后的实际 `/file_search/file_search` 结果名称带有 U+0001 和 U+0002，分别包围匹配文字。普通目录中的同一文件名称没有这两个字符。当前直接保留标记导致选中文件后下载入口被名称安全检查禁用；路径与实际 file info 仍能保持原身份。

匿名官方代码也有一致证据：`official-85365-1b18201a.js` 的 `formatHighlight` 把 U+0001/U+0002 转成高亮 span，并先转义文本；`official-572-c43236f8.js` 识别文件类型前去掉这两个字符；官方 index 同样在扩展名分类前去除标记。

后续修复只应从索引搜索的显示名称去除这两个已确认的协议标记，保留 path、实际文件名校验和其他控制字符拒绝规则。不能把显示名称当作文件身份，也不能引入未经转义的 HTML 或放宽下载安全校验。
