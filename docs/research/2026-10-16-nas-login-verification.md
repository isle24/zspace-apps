# NAS 新设备登录验证协议核验

证据来自实际运行的极空间官方 Web 静态包，2026-10-16 核对 `LoginEmbed` 的发送、检查验证码和登录流程，以及 API 导出模块。没有发送真实短信，也没有将真实账号密码带入测试。

1. NAS `/key/pub?signme=1` 返回新鲜 RSA 公钥与 `sign`。初次登录仍只向所选 NAS 提交 RSA 加密账号、密码。
2. NAS `/auth/login` 返回 `N001414` 时，官方 UI 进入新设备验证。验证标识使用该 NAS 返回的 `sign`，兼容回退至 NAS ID。
3. 用户主动发送验证码：从 `https://api.zenithspace.net/key/pub` 获取 `key`、`key_id`；用此公钥加密账号，向同域 `/sms/usend` 提交 `key_id`、`nasid`、`username`、`type=new_device`。
4. 检查验证码时重新获取云公钥，向同域 `/sms/ucheck` 提交 `key_id`、`nasid`、加密账号、`sms_code`，读取成功数据中的 `sms_proof`，兼容 `email_proof`。
5. 重新取 NAS 公钥，将 `sms_proof` 与加密账号、密码提交给原 NAS，成功后建立正常会话。

云端发送接口只要求成功状态；它的 `data` 可以为空。公钥与校验接口仍要求对象数据。错误只显示固定格式的官方错误码，不回显服务端任意消息。

云端请求限定上述三个 HTTPS 接口、`credentials: omit`、禁止重定向，不发送 NAS Cookie、token 或密码。每次请求超时 15 秒、响应上限 64 KiB；验证状态仅存内存，绑定设备、账号、地址与登录代次，五分钟过期。取消、修改账号／地址、登出及过期都会隔离晚到响应。没有提供跳过 NAS 验证的入口。

匿名取云公钥已验证返回 200，并允许无凭据跨域请求。验证码成功、错误、非对象发送成功数据、冷却、取消、超时、过期与晚到响应通过本地协议夹具验证；真实 Z4S 的短信送达与完整登录仍待设备现场验收。
