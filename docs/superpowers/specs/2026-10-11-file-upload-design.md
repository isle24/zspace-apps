# PC/H5 文件上传设计

延续已批准的客户端设计：文件上传调用官方接口，目标为用户选定的新目录，保留既有资料；PC使用Tauri，手机阶段使用H5。Go仍只负责独立商店，不增加NAS上传REST服务。

源文件由正常系统文件选择提供。PC将选择结果保留为原生内存中的不透明引用，不向渲染器暴露本机绝对路径；H5保留浏览器File对象。各平台按最多2MiB读取，返回同一完整MD5、完整SHA-256、官方UUID和快速指纹契约，支持取消；不得整文件缓存或把采样结果称为完整校验。浏览器计算放入Worker；PC使用原生工作线程和成熟RustCrypto增量实现，在原生层读取已选择的句柄，避免完整校验时源字节来回跨IPC。跨平台算法以独立已知值核对，MD5/SHA1只兼容既有文件协议，不用于凭据或安全签名。

上传由当前客户端自身正常NAS会话授权，固定官方路径、原点、请求字段和无重定向边界。凭据只在SDK与必要官方传输中使用，不进入任务快照、URL、日志或Worker。部署目录/eMMC约束不因上传开发改变。

目标目录、路径和名称由实际NAS身份及用户输入构造；目录就绪不证明新inode所有权。创建前检查目标状态，存在或未知时保留并要求用户另选名称/新目录。文件冲突不覆盖旧资料：让用户在新目录保留新副本。先实现明确的新目录单文件链路，再扩展受控多文件队列；完整上传目标不缩为仅小文件演示。名称、父目录、源身份、partial记录和每次await的会话/取消状态都需核验。

分片只在官方成功确认后推进。最后一片发送完整MD5和complete标志，读回目标名称/类型/大小；实机阶段在自建测试目录对照完整SHA-256验证真实字节及旧marker。无法确认、取消、退出或断线时保留NAS上的未完成数据，不清理或自动重试。暂停/继续仅在当前内存任务及源身份、UUID、服务端partial大小全部吻合时显式进行，不接管未知旧任务。

文件传输控制器独立于Files窗口，关闭窗口不终止上传；明确取消、会话失效或账号切换停止旧会话工作。UI显示校验、上传、已确认字节、暂停/取消/失败和真实完成状态，屏蔽底层原始异常及本机路径。任务中心同时区分上传、下载、商店安装。

每个源码任务单独TDD与审查。先合成来源/官方服务进行边界和字节检查，再正常真实NAS登录验收。5055的上传路由、空文件、partial响应、冲突保护、native源身份和正式H5/HTTPS均需具体证据；不能从哈希测试推断网络上传成功。已有客户端/商店、已批准NASSSO、下载及全部旧包/数据保持完整。
