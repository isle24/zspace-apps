# 第三方商店登录可见性

日期：2026-10-11（Asia/Shanghai）

用户已确认：独立入口先登录，登录后才可查看和操作商店；自己开发的三方客户端可以复用当前 NAS 登录；仅 NAS 管理员允许免密进入并管理。

## 行为

- 直接打开独立商店时，显示商店登录页，不加载和展示应用目录、分类、实例、安装任务、存储信息或安装向导。
- 正常使用独立商店管理员账号登录后，显示完整商店。
- 从三方客户端进入时，由现有固定 NAS 来源和商店实例绑定机制交换当前 NAS 管理员会话；无需重新填写商店密码。首次目标信任继续沿用现有流程。
- NAS 普通账号不能交换商店会话，前端传来的角色、已登录标记或 URL 参数不能作为授权依据。
- 退出、会话过期、NAS 权限撤销或商店切换后，立即隐藏商店内容；旧请求结果不能重新显示或覆盖新会话。
- 商店登录状态只保存在内存；不新增密码或 NAS token 的持久化。

## 后端契约

- `GET /api/store/catalog` 必须通过现有商店认证；匿名、过期、已注销会话均返回 `401 store_auth_required`。
- `GET /api/store/status` 的匿名响应仅保留登录和显式绑定所需的 `configured`、`setupRequiresLoopback`、`nasAuth`。其中 NAS 来源和商店实例 ID 属于既有绑定校验契约，不包含用户凭据、目录或应用内容。
- 完整的引擎模式、就绪状态和运行提示仅返回给通过现有认证的会话。匿名状态查询不调用执行引擎。
- 登录、首次初始化、NAS 会话交换、注销继续使用既有 API 和管理员校验；不更换 SQLite 格式、管理员或实例身份。
- 会话交换继续重新核验固定来源的 NAS 管理员身份；普通 NAS 用户明确拒绝。

## 实现路线选择

推荐：仅修改现有商店组件及商店请求相关代码，后端同时保护目录和完整运行状态。保留当前构建结构，能最小范围交付明确的登录规则；客户端登录、文件、媒体、桌面和主题交给 dsh。

替代：迁出独立 `apps/store`，建立纯商店 SDK 和构建发布链，给 dsh 提供内嵌商店接入契约。两边可以独立发布，但涉及组件和样式迁移，交付范围更大。

仅改后端并等待客户端适配不能独立交付当前规则：现有客户端目录请求始终匿名，即使已登录也会收到 401，因此不采用该路径。

## 验证

后端回归验证匿名目录拒绝、匿名 status 不暴露运行信息且不探测引擎、有效商店会话可读目录/状态、注销及过期拒绝读取、NAS 管理员可读而普通账号交换被拒绝。

界面回归验证登录前只有登录/授权界面且没有目录请求，登录后才请求并显示目录，注销后内容清空，迟到响应不能越过会话边界；内嵌商店沿用现有 NAS 管理员免密绑定和撤销回归。

真实极空间操作只允许通过 `sshbind exec zspace`。本轮不删除、移动或接管 NAS 数据，不改官方 5055、全局 Docker 配置或已有应用。FNOS 测试虚拟机的 SSH 访问与这些源码回归分开记录。
