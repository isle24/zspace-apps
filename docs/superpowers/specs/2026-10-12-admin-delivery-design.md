# 三方 UI、商店与管理员能力交付设计

用户已明确授权实现全部问题并部署到服务器，本轮直接实施。

1. 保留现有官方 NAS 接口客户端与独立商店的边界，提供两个 Docker Compose 入口及客户端 GitHub Actions 构建。
2. 管理员使用已配置的 OpenAI 兼容 AI 服务辅助填写应用名称、标识、简介、图标、分类、版本、端口、数据目录及安装变量。AI 结果是可编辑草稿，经过相同服务端校验和镜像核验后才能发布。密钥仅加密存储，不回显。
3. 管理员可以粘贴 Compose 导入草稿。保持已审核的容器权限模板，云后台当前支持单服务 Compose 导入为可编辑草稿；多服务和无法保留的危险或未知配置明确报错，不丢弃任何服务。NAS 的 Compose 独立执行入口支持多服务；不执行粘贴的主机命令。
4. 图标在编辑器与列表显示预览，优先后端不可变缓存，原始 GitHub 地址兜底。现有目录素材可通过受限目的地代理缓存。
5. 服务端镜像缓存池配置容量、开启状态并显示已用空间、热度、缓存状态。缓存完整 linux/amd64 镜像，由内容校验保护。安装首先读取缓存，失败后回退原始 digest 引用。超过预算淘汰低热度旧条目；不删除宿主 Docker 镜像或用户数据。
6. 线上管理员可扫码建立 TOTP，在提交正确六位动态码前不绑定；启用/停用需要密码和动态码验证，登录启用后要求动态码。本地测试不强制。生产部署要求未绑定管理员进入绑定引导，业务接口受限，防止上线即锁死。
7. 更新 nj-game 的 zstore 管理服务，保留数据库、用户、签名密钥及备份。NAS 部署仅更新本项目服务；不删除原有容器、文件和数据。更新有版本快照和健康检查。

验证：针对 AI/Compose、2FA、图标与镜像容量淘汰新增行为回归；执行 Go、三个前端类型/单测/构建，Docker Compose 配置校验，生产健康与管理页面验收。Actions 必须检查实际运行结果，未完成部分明确记录。
