# 独立 NAS 商店 Docker

用户明确要求商店可单独部署并自行创建账号，不要求第三方桌面。现有中央目录后台镜像与 NAS 商店安装服务用途不同，保留现有部署和镜像，不复用 NAS 管理员身份来满足独立部署。

## 交付

新增 `isle204/zspace-shop` AMD64 镜像。一个 Compose 引导服务通过已授权的本机 Docker socket 自动创建受管商店容器；使用相同镜像内的 Go 服务、商店前端、Python 与固定版本 Docker 工具。运行服务仍保持非 root、只读根文件系统、独立私有数据目录、精确容器身份证明和既有安装校验。引导服务负责初始化与生命周期，不要求 SSH、第三方桌面或中央 PostgreSQL。

Compose 必须设置 NAS 的局域网 IP，端口默认 18443。数据根默认选择 Docker 缓存所在物理 /data_* 数据盘上的独立专用目录；可显式选择另一个全新专用目录。只创建新目录，不修复已有目录权限、不接管其他服务。控制卷保存部署 receipt，停引导容器时停止它确切创建的服务；重启重新核验身份再启动同一容器，不删除应用、容器、镜像和数据。

## 本地账号

现有独立商店保存 bcrypt 密码和有期限的内存客户端会话。新增明确的 `--setup-mode lan`；默认仍为 loopback，现有 NAS 身份模式与中央后台不启用此模式。LAN 模式仅接受直接同源局域网请求，拒绝公网来源、代理身份头与外站请求。首次创建一个管理员，之后注册入口关闭，只允许密码登录。前端按 bootstrap 的设置显示网页创建账号说明。

## 验证

先覆盖 LAN 初始化边界与引导服务的身份、路径、重启和保留数据行为，再构建镜像。在新 NAS 端口和新专用目录完成网页首次创建、退出、密码登录、存储发现、实际安装和应用访问。创建测试账号的密码只存在测试进程内存，不写入命令、报告或仓库。发布 DockerHub 镜像并更新 GitHub 的 Compose 文档，明确 AMD64 与自动创建受管服务的行为。
