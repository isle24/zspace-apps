## 原生保存源码

检查点 `cd6e9d9`：直接使用官方单文件下载接口，以当前会话的不透明引用调用 Rust 保存命令。保存位置只来自系统对话框，固定父目录后仅创建新文件；不截断已有文件、空文件或符号链接。流式保存完整内容，校验文件身份、大小、范围及 EOF，flush/sync 后才完成。取消或失败保留新建的未完成文件，并明确标识。

根执行前端304项测试、Rust38项测试、类型及格式检查通过；实现者完成前端生产构建与 Rust release 编译。独立复核通过。测试实际比较了大于8MiB的完整输出和既有目标内容，另覆盖目录替换、取消、旧会话、错误响应、媒体引用隔离与 Windows 文件名策略。

真实 NAS 下载头、系统保存对话框、实际 Windows 文件系统和安装包运行仍需验收。普通及加密下载要求附件文件名匹配真实元数据，此假设尚未从当前真实 NAS 响应确认。

## H5 下载源码及浏览器实测

检查点 `62334e4`、取消修正 `c912ab8`。H5 使用同源的本地工作线程交付完整流，并提供显式兼容下载：最大64MiB、有界内存、完整 EOF 校验后才生成 Blob。已开始的流式下载失败后不会自动重试。下载地址不包含 NAS 地址、Cookie、token 或签名；浏览器接收字节与最终磁盘保存结果分别表述。

首轮独立复核发现取消瞬间未观察源 Promise 拒绝的问题；已修复两处辅助函数并加入回归。最终实现者352项前端测试、类型及生产构建通过；根重跑48项覆盖测试通过，重新复核通过。

当前内置浏览器没有完成工作线程生成的下载，最小静态工作线程对照也没有产生下载事件；普通 HTTP 与 Blob 对照可以实际保存。因此大文件默认流式方式仍需其他浏览器、正式 HTTPS 和移动端验收，不据此宣称所有浏览器或 Safari 均不支持。未把实验性的 Content-Length、子窗口或权限放宽加入生产实现。
