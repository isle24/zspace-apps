# 可访问性巡检：名字与焦点

之前三十多轮都没系统看过可访问性。这轮补上，检查两件能客观判定的事。

## 检查什么

`scripts/a11y-audit.mjs` 逐个窗口打开，对每个**可聚焦元素**
（`button / a[href] / input / select / textarea / [tabindex]`）检查：

1. **有没有名字** —— 图标按钮若没有可访问名字，屏幕阅读器只会念"按钮"。
   取名字的顺序：`aria-labelledby` → `aria-label` → 文本 → `title` → 关联 `<label>` → 占位符。
2. **有没有焦点样式** —— 键盘 Tab 过去必须看得见自己在哪。
3. **图片有没有 `alt`**。

## 为什么焦点用"查样式表"而不是"真按 Tab"

应用用的是 `:focus-visible`（15 处）。这个伪类**只在键盘交互之后成立**：

- 程序化 `el.focus()` 不触发它（实测 `matches(':focus-visible')` 为 false）；
- `el.focus({ focusVisible: true })` 在这个 Chrome 里也无效；
- 真按 Tab 需要页面可见，而本环境的页面在后台（见 `2026-10-12-window-interaction.md`）。

所以改成**解析样式表**：收集所有含 `:focus-visible` / `:focus` 的规则，
去掉伪类后用 `el.matches(选择器)` 判断每个元素是否被覆盖 —— 能客观回答
"这个元素到底有没有焦点样式"，且不受输入模态影响。

## 第六个"尺子坏了"：`for...of` 读不到 CSSRuleList

第一版检查报**「496 个元素全都没有焦点样式」**，看着像整个应用没有键盘可达性。

查下去是遍历方式的问题：

```js
for (const rule of sheet.cssRules) { … }          // 2005 条规则里只枚举出 3 条
for (const rule of Array.from(sheet.cssRules))    // 2005 条，正常
```

用 `Array.from` 之后同一页面数出 **26 条焦点规则**，结论从"全站没有"变成"全部覆盖"。

至此同类教训已有六条，都是**测试说功能坏了、其实是测试自己坏了**：

1. 对比度合成把 alpha 置 1 → 凭空 98 个问题
2. 窗口类名写错（`.window` / `.app-window`）→ 量了整个桌面
3. 后台标签页 + `loading="lazy"` → 图片永远 0
4. 后台窗口 + CDP 输入不送达 → 交互项全部"失败"
5. 事件名映射留在 Node 侧 + `ev()` 吞异常 → 一个事件都没派发
6. `for...of` 读 CSSRuleList 只拿到 3/2005 → "全站没有焦点样式"

前四条已在各自脚本里加了前置检查或说明，第 5、6 条这次也补上了。
