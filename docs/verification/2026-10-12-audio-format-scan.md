# 音乐库格式普查：哪些歌在浏览器里注定放不了

只读扫描（本机 SSH，未改动任何文件）。目的：把"音乐能播放"这句话说到**具体数字**，
而不是笼统地"能播"。

## 库的构成

音乐根：`/tmp/zfsv3/sata14/public/音乐`（= 设备上的 `/sata14/public/音乐`），
**184,119 个文件**，其中音频 **76,914 个**（与设备 API 报的 76,858 首一致）。

| 扩展名 | 数量 | 占比 |
| --- | --- | --- |
| `.flac` | 57,397 | 74.6% |
| `.mp3` | 13,119 | 17.1% |
| `.m4a` | 2,181 | 2.8% |
| `.wma` | 2,145 | 2.8% |
| `.wav` | 1,552 | 2.0% |
| `.ape` | 309 | 0.4% |
| `.dsf` | 159 | 0.2% |
| `.mp4` | 52 | 0.1% |

**400 个随机抽样**用 ffprobe 验真实编码：flac 287、mp3 90、wmav2 10、pcm_s16le 4、
alac 4、aac 3、ape 2 —— 与扩展名完全吻合，**抽样里没有一例"改名"**。

## 结论：约 3.5% 放不了，而且原因不在客户端

| 类别 | 数量 | 浏览器能解码？ |
| --- | --- | --- |
| `.wma`（WMA v2） | **2,145** | ❌ 没有解码器 |
| `.ape`（Monkey's Audio） | **309** | ❌ 没有解码器 |
| `.dsf`（DSD） | **159** | ❌ 没有解码器 |
| `.mp4`（当作音频） | **52** | ⚠️ 视封装而定 |
| **改名成 `.mp3` 实为 WMA** | **40** | ❌ 同上 |
| 合计 | **≈ 2,705 / 76,914 = 3.5%** | |

- 其余 **96.5%**（FLAC / MP3 / M4A-AAC / ALAC / WAV）浏览器都能直接解 ——
  **设备侧只提供"无损原流"，不做音频转码**（实测 `play_format_list` 只有 `OP:无损原流`），
  所以这 3.5% 不是我们这一层能修的：换成官方桌面端（自带解码器）才能放。
- 那 40 个"改名 mp3"集中在同一个下载合集
  （`1.15TB超大音乐合集，转存即听/` 下的网易云 TOP100、经典粤语等子目录），
  怀疑是转存时被批量错误命名。
- 全量清单已存档：`docs/verification/data/browser-unplayable-audio.txt`（2,665 行，相对音乐根路径）。
  其中 2,506 个在 `音乐大全/`，159 个在 `PT/`。

## 客户端侧的表现（已实现）

碰到这类文件，播放器会**说清楚原因**并给一条出路（见
`docs/verification/2026-10-12-music-queue-codec.md`）：

> 浏览器无法解码这个文件的音频编码（常见于把 WMA/APE 之类的文件命名为 .mp3）。
> 设备对音乐只提供原始流、不做转码，所以这一首放不了；换一首或改用官方桌面端。

外加一个 **「跳过这一首」** 按钮。

## 备注

- 用于核对的全库文件头逐个扫描（77k 文件、含 ID3 跳转）在 FUSE 挂载上太慢，
  到本轮结束时仍在后台跑；上面的数字来自**按扩展名的完整枚举 + 400 抽样 ffprobe + 13,119 个 mp3 的逐个文件头检查**，
  已经能支撑"3.5%"这个结论。
