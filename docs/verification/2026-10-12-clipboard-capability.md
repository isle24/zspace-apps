# 剪切板监听：实测它在这个部署里**不可能生效**，于是改成如实说明

## 实测发现

本轮去真机验证目标里写的「剪切板监听」，结果是：

```js
window.isSecureContext  // false          （部署是 http://192.168.3.56:18436）
location.protocol       // "http:"
typeof navigator.clipboard  // "undefined"
```

**`navigator.clipboard` 只在安全上下文（HTTPS / localhost）里存在**。在 http 部署下它压根没定义，
所以：

- 「读取剪切板」按钮永远走 catch 分支；
- 「自动监听剪切板」开关更糟 —— 轮询里的 `catch` 会把 TypeError 静默吞掉，
  开关看着打开了，实际每 1.5 秒空转一次，**永远不会生效**。这是最坏的一种：
  界面在暗示一个不存在的能力。

## 修法

1. 新增能力探测 `clipboardSupport()`：`isSecureContext` + `navigator.clipboard.readText` 是否存在。
2. 不可用时：按钮与开关**置灰**，并在下方写明原因与替代方案：

   > 浏览器只在 HTTPS 或 localhost 下允许读取剪切板；当前是 http:// 访问。
   > 请用 ⌘V 直接粘贴，或改用桌面客户端。

3. 不可用时**不启动轮询**（不再空转）。
4. 可用时行为不变（仍是每 1.5 秒读一次、识别到链接自动追加，带「已从剪切板捕捉到链接」提示）。

| 手动输入磁力链 | 输入 `magnet:?xt=urn:btih:…` 后**没有**「不是受支持的链接格式」告警 ✓（未提交任何任务） |

## 想真正用上剪切板，有三条路

1. **HTTPS 部署**（或 `localhost` 转发）—— 浏览器就会放开剪切板；
2. **原生客户端**：Tauri 的 webview 里 `isSecureContext` 是否成立**我没有实测**（发布版没开 devtools），
   若同样不成立，界面会显示同一条说明；真正的原生做法是用 Tauri 剪切板插件（需要新增依赖与权限，
   要你点头我才加）；
3. 手动 ⌘V —— 现在就能用，且是唯一在所有环境下都成立的方式。
