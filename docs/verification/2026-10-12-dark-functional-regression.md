# 深色模式下的功能回归

之前深色只做过**对比度**检查，没做功能回归。这轮在深色主题下把全部功能重跑一遍。

## 结果：全绿，0 控制台异常

| 项 | 实测 |
| --- | --- |
| 主题 | `data-theme=dark` 全程保持 |
| 文件管理 | 20 行、排序按钮（名称/大小↓/时间）、选中文件后预览图 `naturalWidth>0` |
| 相册 | 缩略图 **20/20**；大图查看器打开、`1 / 20`、图片加载；`→` 翻到 `2 / 20`；`Esc` 关闭 |
| 影视中心 | 海报 **20/20**；进入影片 → 播放：`readyState=4`、`currentTime=8.1s`、时长 **6368s** |
| 音乐 | 播放：`readyState=4`、`currentTime=7.8s`；歌词面板 **35 行**且当前行高亮；队列 **20 行**且有当前项 |
| 下载中心 / 应用商店 / 任务中心 / 存储管理 / Docker / 远程访问 | 均渲染真实内容，无原始 JSON 倾倒 |
| 控制面板 | 网络 **5 张网卡**、系统设置 **6 个分组** |
| 控制台 | **0 异常、0 error 日志** |

## 这轮又踩了一次"尺子"：懒加载图在后台标签页里永不加载

回归脚本第一次跑时，**相册与影视的图片全部报 `loaded: 0`**，看上去像深色模式把图弄坏了。查下去：

```
img.complete = false      currentSrc = ""      （浏览器根本没开始加载）
新建 Image() 加载同一 URL  → 正常（600×900）
document.hidden = true    visibilityState = "hidden"
把 loading 改成 eager 再重设 src → 20/20 全部加载
```

结论：**不是应用的问题**。Chrome 对 `loading="lazy"` 的图片，在**页面处于后台（`document.hidden`）时会无限期推迟加载**；
我那个用来做自动化的 headless 窗口长期在后台，所以量到的永远是 0。
之前几轮量到 "20/20" 是因为那时窗口在前台。

- 我们的用法本身是对的：289 部影片的海报墙就该懒加载；
- 但如果**以后要写自动化去验图**，必须先 `Page.bringToFront` 或把 `loading` 置为 eager，否则量出来的是测具的问题。

这条已写进 `docs/verification/README.md` 的纪律里（"先验尺子再信数字"的第三个实例）：
1. 对比度合成把 alpha 置 1 → 凭空报 98 个问题
2. 窗口类名写错（`.window` vs `.app-window`）→ 量了整个桌面
3. 后台标签页 + 懒加载 → 图片永远量到 0
