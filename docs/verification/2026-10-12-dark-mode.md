# 深色主题巡检与修复

之前所有验收都在浅色下做的。这轮写了一支**对比度巡检脚本**
（`scripts/dark-contrast-audit.mjs`）：切到深色，逐个打开每个窗口，对每个"直接含文字"的元素
计算文字色与实际背景（沿祖先链合成半透明背景）的对比度，低于 WCAG AA（正文 4.5:1、大字 3:1）就报出来。

## 修掉的真问题

| 问题 | 根因 | 修法 |
| --- | --- | --- |
| 账号菜单三项**完全看不见**（1.0:1） | 旧的 `styles.css` 把按钮底写死成浅蓝 `#edf3fd`，深色下变"浅底浅字" | 菜单按钮改用 `--fn-fill-*` / `--fn-text-*` 令牌 |
| 媒体左栏分类/导航 1.84:1 | 我写的 `var(--text-2, #4a4a4a)` 是**不存在的变量**，fallback 落成浅色灰 | 全部换成 `--fn-text-2`；深色再补 `.active` 用白字 |
| 系统侧栏选中项 1.65:1 | 旧样式写死浅蓝底 `#e0ecff`，与我改的浅蓝文字撞在一起 | 深色下选中底改用 `color-mix(brand 22%)` |
| Docker 状态徽标 2.32:1 | 深绿文字压深底 | 深色下换亮绿 `#4ade80` |
| 排序控件 / 商店 chips 选中态 ~2.6–3.0:1 | 深色下仍用 `#0066FF` | 深色下换 `--fn-brand-3` |
| 我自己新样式里的**粉彩底** | 用 `--fn-brand-0/1/2` 当背景，而深色主题**没有重定义**这几个粉彩 → 深色下仍是浅蓝 | 底色改 `color-mix(in srgb, var(--fn-brand-5) N%, transparent)`，两种主题都成立 |

## 顺带修掉的两个"验证工具"的 bug（值得记）

第一版脚本报 Docker 有 98 个问题，但**截图看起来完全正常**。查下去是脚本自己的错：

1. **合成半透明背景时把 alpha 强行置 1** → 4% 白 + 深色底被算成纯白，
   Docker 卡片全被判成"浅底浅字"。修成保留 alpha 的 alpha 合成后，同一个窗口降到 30 → 再修真实问题后到 0。
2. **窗口类名写错**（`.window` vs 实际的 `.app-window`）→ 选择器落空后去量了整个桌面。
3. **账号菜单没关**，挡住后续点击，导致"每个窗口都打不开却都报了 30 多个问题"。

教训：**数字对不上直觉时，先怀疑尺子**。这三条都写进了脚本头部注释。
