# 重复实现收敛（以及一个"看着像重复、其实不是"的教训）

扫了一遍 `apps/client/src`：把同名函数的重复实现找出来。

## 合并掉的

| 函数 | 原来有几份 | 现在 |
| --- | --- | --- |
| `asRecord`（对象判定，排除数组/null） | 4 份逐字相同 | `modules/values.ts` |
| `asText`（非空字符串） | 2 份逐字相同 | 同上 |
| `asLooseText`（非空字符串 **或有限数字**） | 2 份逐字相同 | 同上 |
| `asNumber`（有限数字或数字字符串） | 2 份逐字相同 | 同上 |

涉及 `SystemNetwork` / `SystemOverview` / `RemoteAccess` / `DeviceTasks` 四个系统视图，
以及 `SystemOverview` 保留的一层宽松包装（那个文件历史上字段访问用 `any`，不动它）。

## ⚠️ 一个"看着像重复、其实不是"的

四个文件里的 `text()` 前两行**完全一样**，我以为是一份实现四处拷贝，
于是合并成一个。结果 **`SystemNetwork.test.tsx` 当场报错**：

```
expected '开启' to be '1'
```

原因：`SystemNetwork` / `RemoteAccess` 的那份**第三行**还多一句

```ts
if (typeof value === "number" && Number.isFinite(value)) return String(value);
```

数字被合并后的严格版判成 `undefined`，于是走了另一条格式化分支，设置值从 `1` 变成了「开启」。

修法不是回退，而是**把两个变体都留下、名字区分清楚**：

- `asText` —— 只认非空字符串
- `asLooseText` —— 另外接受有限数字

并补了 4 条用例把差别钉住（其中一条专门写 `asText(1) === undefined` 而 `asLooseText(1) === "1"`），
注释里也写明了"我在合并时就是在这里栽的"。

## 没动的

- `formatBytes`：`common.tsx` 要 1 位小数、到 GB；`ResourceWidget` 要 2 位小数、还到 TB ✗
  **是两套显示要求，不是重复**。合并会改变界面上的数字，所以不碰。
- `api/official-nas.ts`、`workers/*` 里的 `text` / `record` / `hex`：属于协议层，
  语义与视图层不同，也不动。
- 商店组件（Codex 范围）一律不碰。
