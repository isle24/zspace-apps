# 文档引用检查（106 篇，11 处烂链已修）

## 为什么做这个

验收文档已经五十多篇、互相引用。链接最容易悄悄烂掉：文件改名、删了数据文件、
在文档里写成"仓库根相对路径"（Markdown 实际按**文件所在目录**解析）——
单测不会管这些，接手的人点进去 404 才发现。

所以写了个检查器 `scripts/docs-check.mjs`，扫 `docs/**/*.md` 与根 `README.md`：

1. **Markdown 相对链接**指向的文件必须存在（按文件所在目录解析）；
2. 反引号里写出的**仓库内路径**（`docs/…`、`apps/…`、`scripts/…`）必须存在。

外链（http/https）与锚点跳过。

## 查出 11 处，全部处理

| 类型 | 数量 | 处理 |
| --- | --- | --- |
| 链接写成了"仓库根相对"（放错基准目录） | 4 | 改成文件相对（`../design-assets/…`、`../research/…`） |
| 计划文档里列的**计划产出**（`docs/research/validation/*.md`） | 7 | 没有按那名创建；**不删也不藏**，在行尾加 `<!-- docs-check: planned -->` 标记，并在文首补一段说明指向实际证据 |

第二类特意**不是**简单忽略：标记是显式的、可审查的，读者知道"这里本来是打算产出的"，
而不是被静默跳过。

## 接入

`verify.sh` 离线档新增一项：

```
文档引用检查     PASS     文档引用检查通过（106 篇）
```

以后改名或删文件忘了改引用，会在离线验收里立刻报出来。

## 顺带说明：这轮没有删任何历史文档

原计划是"把被取代的旧记录合并掉"。看了一遍引用关系后**放弃了删减**：

- 那些 10-10 / 10-11 的文档虽然描述的是中间状态，但里面有些**决策依据是唯一的**
  （同源部署的由来、商店对接过程、飞牛几何实测）；
- 删掉换来的只是"文件数少一点"，而 `STATUS.md` 已经解决了"从哪看起"的问题。

改成**保证现有文档不烂**，比**减少文档数量**更实在。
