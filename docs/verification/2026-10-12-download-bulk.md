# 下载中心：批量操作（全部开始 / 全部暂停）

## 端点与参数（真机实测 2026-10-12）

| 调用 | 结果 |
| --- | --- |
| `POST /downloader/stop/all`（form 空体 或 JSON `{}`） | **200 success** |
| `POST /downloader/start/all`（同上） | **200 success** |
| `POST /downloader/del/all` `{}` | `N202003 参数错误`（需要 `type`） |
| `POST /downloader/del/all` `{type:"complete"}` | **200**（0 任务时调用，未删除任何东西） |
| `POST /downloader/{stop,del}` 带 `id`/`gid`/`hash`/`ids`/数组/空体 | 全部 `N202003 参数错误` |

关键线索：官方前端这些包装函数是 axios `data: t`，**默认发 JSON**，不是表单。
这也是我们一开始全用表单探测失败的原因（`start/all`、`stop/all` 两种编码都能过）。

## 做了什么

- SDK 新增 `downloads.startAll` / `downloads.stopAll` 两个操作。
- 下载中心头部加 **「全部开始」「全部暂停」** 两个按钮；发送中禁用，返回后刷新列表，
  并把结果如实显示成一行状态：
  - 成功 → 「已请求全部暂停（设备返回 200）」
  - 失败 → 「操作失败：<设备返回的错误>」
- 「任务操作」这项统计从含糊的「能力待验证」改成具体的
  **「全部开始 / 全部暂停 已验证」**。

## 刻意**没做**的两件事

1. **单任务暂停/继续/删除**：参数名无法确定（见上表），设备上 0 个任务也无从反推。
   宁可少两个按钮，也不猜一个可能删错东西的接口。
2. **「清空已完成」**：`del/all {type:"complete"}` 确实返回 200，但**无法确认它是否连带删除
   已下载的文件**。删除类操作在没有确认语义之前不提供。

## 实测

- 按钮齐全：`添加下载 / 全部开始 / 全部暂停 / 刷新状态`；统计显示 `0`（任务数）、`已连接`、
  `全部开始 / 全部暂停 已验证`。
- 点「全部暂停」→ 状态行 **「已请求全部暂停（设备返回 200）」**，按钮恢复可用 ✓。

## 测试

`modules/DownloadBulk.test.tsx`（2）：按钮发出的是两个已验证的操作名并显示成功文案、
设备报错时如实显示错误而不是假装成功。全套 **53 文件 / 1143 用例全绿**。
