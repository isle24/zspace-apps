# 错误处理审计：把每个 catch 翻一遍

这类问题最像前面那些"静默失败"：出错的地方不吭声，界面看起来一切正常。
所以这轮把 `apps/client/src` 里**所有 catch 块**抓出来分类。

## 分类结果

| 类别 | 数量 |
| --- | --- |
| 空吞（只有注释说明为什么可以吞） | 18 |
| 只打日志、不给用户任何反馈 | **0** |
| 有实际处理（回落 / 报错 / 状态） | 119 |

**"只打日志"是 0** —— 这是最值得说的一条：这个项目里没有"出错了只写 console，
界面上假装成功"的写法。

## 18 处空吞逐条看过，理由都成立

抽样：

| 位置 | 吞掉的是什么 | 为什么可以吞 |
| --- | --- | --- |
| `App.tsx` clearStoredSession | cookie 清理失败 | 登录页照样能用 |
| `App.tsx` 主题持久化 | localStorage 写失败（隐私模式） | 不阻塞界面 |
| `App.tsx` 会话恢复 | 某个来源恢复失败 | 代码里会试下一个来源 |
| `Files.tsx` 排序偏好读写 | localStorage | 读不到用默认、存不了不影响使用 |
| `VideoChrome.tsx` 续播位置 | localStorage | 不阻塞播放 |
| `DownloadCreate.tsx` 剪切板轮询 | 无焦点/未授权 | 静默等下一次（能力探测已另行处理） |
| `Files.tsx` 批量下载单项 | 单个文件下载失败 | 不打断整批，且**任务中心里有该任务的失败状态**（不是无声无息） |

## 改掉一处"看着像成功、其实少了东西"的

`api/operations.ts` 的「全部影片」是按媒体库逐个取再合并（官方接口强制要
`classification_id`）。原来某个库读失败时：

```ts
} catch {
  // 单个库里没有可读内容时不该让整个"全部影片"失败
  return { total: undefined, items: [] as Item[] };
}
```

整页不失败是对的，但**用户只会看到"片子变少了"**，没有任何提示。

现在把失败的库名带出来，并在界面上如实说明：

> ⚠ 2 个媒体库这次没读出来：电视剧、短剧

两条用例覆盖：保留其它库内容并列出失败库名（总数只统计成功的那部分）、
全部成功时不产生失败列表。全套 **54 文件 / 1154 用例全绿**。
