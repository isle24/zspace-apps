# 文件管理：多选与批量下载

之前只能一个一个点开文件，没有多选。现在按桌面文件管理器的通用习惯补齐。

## 操作

| 操作 | 行为 |
| --- | --- |
| `⌘` / `Ctrl` + 点击 | 切换该行的选中状态（不打开预览）；锚点跟着最后一次点击走 |
| `Shift` + 点击 | 从锚点到当前行连选 |
| 普通点击 | 与原来一致：文件夹进入、文件打开预览；同时清空选择 |
| `Esc` | 清空选择 |
| 提示行 | 未选中时显示「⌘/Ctrl 点选、Shift 连选，Esc 取消；选中后可一次下载多个文件」 |

## 选择条

选中后表格上方出现一条：

```
已选 3 项   合计 4.0 MB   [下载所选]  [清除选择]   进度文本
```

- 合计大小只累加设备真实返回的 `size`，缺大小的项计 0 并显示「合计大小未知」。
- **批量下载**复用既有下载管线（`FileTransfersController.download`，与「下载到本机」同一个），
  **逐个顺序执行**而不是并发 —— 免得一次性弹出一堆浏览器下载；每个任务都进任务中心，
  其中一个失败不打断整批，进度文本显示「正在下载 n / N」。
- 文件夹不参与批量下载（会提示「文件夹需要逐个打开」），因为设备侧是按单文件准备的。

## 实测（真机，M.2存储11 目录 35 项）

- 20 行渲染 ✓，提示行显示 ✓
- 选中 3 行 → 选择条 `已选 3 项 · 合计 4.0 MB`，`.file-row.picked` 3 行，行上有蓝色底与左侧色条 ✓
- 「清除选择」→ 选择条消失、`picked` 归零 ✓

## 顺带被守卫拦下的一次

皮肤守卫测试要求 `fnos-files.css` **只能使用 `--fn-*` 令牌**、不得出现字面色值。
我第一版写了 `rgba(10,108,255,.1)` 与 `#0a6cff`，被直接判红；改成
`--fn-brand-0/1/2/5` 并通过。这正是那条守卫存在的意义 —— 换肤不允许夹带私有颜色。
