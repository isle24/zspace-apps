# 文件列表排序

## 先确认：设备**不排序**

实测（真机 2026-10-12）在 `/v2/file/list` 上依次试了：

| 参数写法 | 结果 |
| --- | --- |
| `sort=size&sort_type=desc&order=desc` | 顺序不变 |
| `sort=size&order=desc` | 顺序不变 |
| `sort=name&order=desc` / `sort=time&order=desc` | 顺序不变 |
| `sortby=name` / `name_asc` / `name_desc` / `size` / `size_desc` / `mtime` / `mtime_desc` / `ctime` / `ctime_desc` | 顺序**全部不变** |

（`sortby` 是官方前端用的参数名 —— 从它的 `getFileList` 包装里看到的，macOS 上还会拼 `_linux` 后缀。即便照抄也不生效。）

所以排序只能**本地做**：界面里三个按钮「名称 / 大小 / 时间」，点同一列切换升降序，
当前列显示 ↑/↓，选择记在 `localStorage`（官方客户端同样记 `_sortByMode` 之类的偏好）。

**范围与实话**：我们一次只取一页，所以排的是**当前页**。文档与界面都按这个说法，
不让人以为它排了整个目录。

## 实现要点

- **中文用拼音排序**：`localeCompare(..., "zh-Hans-CN", { numeric: true })`，
  按码点排会把"张三"排到"李四"前面。
- **缺值永远沉底**：设备没给 `size` / 没给时间的条目，无论升降序都排最后 —— 不参与方向翻转。
- 不修改传入数组（`[...items].sort`），网格视图与列表视图共用同一份排序结果。

## 实测（真机，M.2存储11 目录 35 项）

| 操作 | 结果 |
| --- | --- |
| 默认（名称↑） | `.通过samba删除的文件`、`.DS_Store`、`11.txt`、`115缓存`、`第二季度工作总结(1).xls` |
| 点「大小」→ ↓ | 150.6 MB → 61.6 MB → 18.7 MB → 3.9 MB → 455.5 KB ✓ |
| 再点「大小」→ ↑ | 0 B（若干文件夹）在最前 ✓ |
| 偏好记忆 | `localStorage["space-desktop:file-sort"] = {"key":"size","dir":"asc"}` ✓ |
