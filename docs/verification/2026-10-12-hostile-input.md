# 异常输入与压力测试（对抗性检查）

前面三十多轮都在验"正常路径"。这轮反过来：往应用里灌**坏数据**，看它会不会崩、
会不会把 `undefined` / `NaN` 显示给用户。

做法：在页面里拦截 `fetch`，对 NAS 接口返回伪造响应，其余透传。

## 结果：7 种坏输入全部安全落地

| 注入 | 界面表现 | 页面异常 |
| --- | --- | --- |
| 空列表 | 「这里还没有内容 / 设备返回的列表为空」 | 0 |
| 缺字段（`data: {}`） | 同上 —— 不崩、不显示 `undefined` | 0 |
| 超大数值（`size: 9.4e18`、`-5`、字符串 `"很大"`、缺名字） | 四行全部显示 **`—`**（诚实降级，不是 `Infinity`/`NaN`） | 0 |
| 业务错误码 `N999999` | 「暂时无法读取 NAS / 未能完成此请求（N999999）」+ 重新读取 | 0 |
| 返回 HTML（`502 Bad Gateway`） | 「暂时无法读取 NAS / 返回无法识别的数据」+ 重新读取 | 0 |
| 影视接口空列表 | 正常空态 | 0 |
| 音乐接口缺字段 | 正常空态 | 0 |

**可疑文本检查**：所有场景下页面可见文本中都没有 `undefined` / `NaN` / `Infinity` / `[object Object]` ✓

## 会话过期：优雅退出

拦截所有 NAS 接口返回 `401`，然后触发一次列表请求：

```
桌面 -> 登录页（自动）
提示：NAS 登录已失效，请重新登录。
登录页显示：设备地址 192.168.3.56:18436、保持登录、更改设备地址、独立应用商店
```

符合预期：本地状态被清干净，回到登录页，而不是卡在到处报错的桌面上。

## 压力与重复操作

| 场景 | 结果 |
| --- | --- |
| 连点同一个应用图标 **10 次** | 只开 **1** 个窗口（按 appId 去重） |
| 一次开 **11 个窗口** | 11 个窗口、**0 异常**、JS 堆 9 MB |
| 每开一个窗口都保持渲染 | 无白屏、无卡死 |

## ⚠️ 这轮测试的副作用（需要你操作一次）

为了验"会话过期"，我让 NAS 接口返回了 401 —— 应用**按设计**执行了登出，
会话 cookie 被清掉了。而这次登录当时没有勾「保持登录」，所以**凭据没有被保存**：

```
localStorage: 只有 nas-device-id / theme / file-sort，没有凭据
cookies: token 已清除（username / userid 等非敏感项还在）
```

**结论：需要你重新登录一次**（打开 http://192.168.3.56:18436/ ，填账号密码即可；
设备地址已经自动填好，只差账号密码）。抱歉 —— 这是我这轮测试造成的，不是应用故障。

顺带说明：登出后登录页本身是**好的**（地址预填、保持登录、更改设备地址都在），
也就是说这次"副作用"同时也验证了登录页在真实登出后的样子。

> 以后跑 `verify.sh --live` 需要页面处于**已登录**状态；如果看到大量失败，
> 先确认是不是被登出了。
