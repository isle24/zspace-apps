# 键盘可达性与主题跟随：两个"看起来像 bug"的结论

这轮做的是"不用登录也能验的用户路径"里最后两项。**两件都查清了，都不改行为** ——
但其中一件顺手补了说明。

## 1. Tab 跳不到按钮？—— macOS 的平台约定，不是我们的问题

在 WebKit 里按真实 Tab 键走登录页：

```
1 INPUT "NAS 地址"   focus-visible=true shadow
2 INPUT "NAS 账号"   focus-visible=true shadow
3 INPUT "登录密码"   focus-visible=true 无指示
4 (无焦点/回到文档)  ← 之后回环
```

看着像"按钮全都不可聚焦"。但枚举可聚焦元素是 **7 个**，`tabIndex` 全为 0、全部可见：

| 元素 | tabIndex | disabled |
| --- | --- | --- |
| 地址 / 账号 / 密码 输入框 | 0 | false |
| 显示密码按钮 | 0 | false |
| 保持登录 checkbox | 0 | **true** |
| 登录按钮 | 0 | false |
| 独立应用商店按钮 | 0 | false |

原因：**macOS 默认不把 Tab 用于按钮**（"全键盘访问 / Full Keyboard Access" 关闭时，
Tab 只在文本框与列表间移动）。这是 Apple 的平台约定，Safari 与 WKWebView 都是如此 ——
**我们的 Mac 客户端也一样**。所以不是 CSS/JS 能修的东西，记下来免得以后有人去"修"。

> 影响：Mac 上键盘用户默认 Tab 到密码框就停住，需要按 Enter 提交（**实测 Enter 有效** ✓）
> 或打开系统的全键盘访问。这与原生 macOS 应用一致。

## 2.「保持登录」在网页版是灰的？—— 故意的，但**没说为什么**

```
disabled={!isNative()}
```

网页没有原生钥匙串，所以不保存凭据 —— 这是设计（也解释了一个历史现象：
第 35 轮我在**网页版**验会话过期，凭据没被保存，于是登出后无法自动恢复）。

但界面上**没有任何解释**：灰着不说话最容易被当成 bug（我自己这轮就一度当成 bug）。
而且 `disabled` 元素**不参与 Tab**，键盘用户连"这里有个选项被禁用了"都感知不到。

**修法（只加了说明，没改行为）**：

```
保持登录  [灰]  网页版不保存凭据        ← 灰色小字，只在网页版出现
title="网页版不保存凭据；桌面客户端可勾选"
```

一条用例钉住：网页版下 checkbox 置灰、说明文字存在、`title` 含原因。

## 3. 主题是否跟随系统？—— **不跟随，是刻意的**

代码里默认 `light`，只有用户显式选过 `dark` 才深色。`fnos-theme.css` 里那段
`@media (prefers-color-scheme: dark)` 是**故意留空**的，注释写着：

> fnOS 桌面在浅色资源下保持中性浅色，不跟随系统深色；深色只由显式 `[data-theme="dark"]` 开启。
> 这里不再自动切换，避免同一台机器上因系统外观不同而出现"外壳浅色、窗口深色"的混搭。

也就是说：**这是照着飞牛参照实现的决定**，不是漏做。查过、确认是刻意的，**不动**。
（用户可在账号菜单里切换，选择会被记住。）

## 结论

这轮的价值不是"发现 bug"，而是**把三件容易被误判的事查清楚**：

| 表象 | 真相 |
| --- | --- |
| Tab 跳不到按钮 | macOS 平台约定（WKWebView 同样） |
| 保持登录是灰的 | 故意（网页无钥匙串），**已补说明** |
| 主题不跟随系统 | 刻意对齐飞牛参照，**不做** |
