# 窄窗口 / 小屏布局巡检

跟上一轮同样的纪律：**先把尺子验了再信数字**。

## 方法

`scripts/layout-audit.mjs` 把视口改成若干尺寸，逐个打开每个应用窗口，报三类问题：

1. **越界**：窗口内元素右边缘超出窗口右边缘（排除横向滚动容器）
2. **静默裁字**：`overflow-x:hidden` 但内容更宽，且没有 `text-overflow:ellipsis`
3. **整页横向滚动**

脚本带 `--selftest`：往窗口里塞一个 2000px 宽的块和一个静默裁字的块，确认两种都能被抓出来。
**实测自检通过**（否则这一轮的"全部 ok"不算数 —— 上一轮对比度巡检就是尺子坏了，凭空报了 98 个问题）。

## 结果

| 视口 | 说明 | 结果 |
| --- | --- | --- |
| 880×620 | Tauri 客户端的最小窗口尺寸 | **11/11 ok** |
| 760×560 | 比支持的最小尺寸还窄 | 修前 1 个窗口越界 → **修后 11/11 ok** |
| 640×900 | 应用的移动端断点（≤700px） | **11/11 ok** |

合计 **33/33 组合通过**。

## 修掉的一个真问题

**760×560 时文件管理工具栏越界**：`file-search-form` 顶出窗口右边缘 **+116px**，范围下拉 `SELECT` 越界 +58px。
根因是 `.files-module .toolbar { flex-wrap: nowrap }` —— 工具栏被写死不许换行。

修法：允许换行（`flex-wrap: wrap; row-gap: 6px`），窄窗口下搜索框与下拉自动落到第二行。
修后同一视口 **ok**。

> 说明：Tauri 客户端的 `minWidth` 是 880，所以 760 这个宽度在正式客户端里到不了；
> 但网页版可以被拖到更窄（也可以开在手机浏览器上），所以这个修复是有意义的。

## 本轮没有发现的

- 没有整页横向滚动
- 没有静默裁字的元素（省略号或滚动容器都在该在的地方）
- 移动端断点（640×900）下窗口铺满视口，用的是移动布局，没有溢出
