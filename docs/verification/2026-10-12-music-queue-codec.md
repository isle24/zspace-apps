# 音乐队列面板 + 解不了的编码怎么说

## 队列面板（QQ 音乐式）

- 播放条上「播放队列」按钮 → 面板在胶囊上方同宽展开。
- 每行：序号（当前曲换成喇叭图标）· 曲名 · 艺人，当前行高亮并标 **正在播放**；点击切歌；切歌后自动滚到当前行。
- 实测：20 行，`1 / 20` → 点第 4 行 → `4 / 20`，高亮跟着走，面板**保持打开**。

### 顺带修掉的真 bug

`PlayerContent` 是按曲目 keyed 的（换歌会重挂载），所以原先换一首歌，
**队列/歌词面板会被关掉**。已把这两个面板的开合状态提到不重挂载的外层 `Player`，
并加了一条用例钉住（`panels survive a track change`）。

## 有一类歌浏览器根本放不了（已确证）

实测样本：`「名探偵コナン」~メインテーマ-大野克夫.mp3`

| 检查 | 结果 |
| --- | --- |
| `/transcode/audio/play` 返回 | `play_format_list: ["OP:无损原流:127"]` —— **音乐只有原始流，没有转码档位**（视频才有） |
| `/splay/<hash>` 实际字节 | 前 3 字节 `ID3`，ID3 头声明长度 29587，**紧接着就是 ASF GUID `3026b275…`** → 内容是 **WMA**，只是文件名叫 `.mp3` |
| Chrome | `MEDIA_ERR_SRC_NOT_SUPPORTED (4)`，转码重试后依旧 |

结论：这不是客户端的 bug —— 浏览器没有 WMA 解码器，设备也不给音频转码，
**任何网页版都放不了**（官方桌面端用自己的解码器才行）。

所以改成如实说明 + 给出口：
> 浏览器无法解码这个文件的音频编码（常见于把 WMA/APE 之类的文件命名为 .mp3）。设备对音乐只提供原始流、不做转码，所以这一首放不了；换一首或改用官方桌面端。

并在下方给一个 **「跳过这一首」** 按钮（队列里遇到这种文件不用手动找下一首）。
其它失败码仍走原来的「转码重试后仍不可用」文案。
