# 原生客户端登录页：只剩下账号和密码

用户在最早一轮就提过：*"登录界面如果是网页版的，正常从 NAS 过来应该不需要输入地址才对……
正式的不需要……最好参考飞牛，直给账号和密码"*。这轮把它落到了**原生客户端**上。

## 原来的行为

`same-origin.ts` 的规则是：

```ts
if (native) return "";   // 原生 Tauri 客户端没有"同源"概念，必须显式地址
```

于是 Mac 客户端**永远**会显示「设备地址」输入框。即使 `runtime-config.json` 已经给了
NAS 地址，那份配置也只是**预填** `baseUrl`，字段照样显示 —— 用户还是得看着一个不该出现的框。

（更糟的是这份配置**根本没进包**：`build.sh` 先写配置、`tauri build` 内部又跑了一次前端构建，
vite 清空 dist 把 `public/` 里的空默认值拷了回去。上一轮已修。）

## 现在的行为

```ts
const knownOrigin = origin || configuredOrigin;   // 同源 或 部署期配置
const askForAddress = !knownOrigin || showAddress;
```

- **知道地址就不问**：网页版跑在 NAS 上（同源）→ 立刻知道；原生客户端/容器部署 → 配置给出。
- **留了退路**：卡片底部有「更改设备地址」，点开才显示输入框，再点收起。
  不会因为隐藏而没法换设备。
- 副标题显示已知地址（`192.168.3.56:5055`），让用户知道连的是哪台。

## 验证方式：在 WebKit 里伪装成原生客户端

`isNative()` 只认一个全局变量：

```ts
export const isNative = () => "__TAURI_INTERNALS__" in window;
```

所以在 WebKit 里 `addInitScript` 注入 `window.__TAURI_INTERNALS__` 就能走原生分支，
不必真的开 Mac 应用（也开不了 —— 截窗口需要屏幕录制权限）。

| 场景 | 账号 | 密码 | 设备地址 | 副标题 |
| --- | --- | --- | --- | --- |
| 伪装原生 + 有配置 | ✅ | ✅ | **不显示** | `192.168.3.56:5055` |
| 网页版 + 有配置 | ✅ | ✅ | **不显示** | `192.168.3.56:5055` |
| 两者都没有（新增用例） | ✅ | ✅ | 显示，必填 | 连接你的 NAS |

## 测试

`App.test.tsx` 新增 2 条：已知地址时隐藏地址栏且可手动展开、
没有任何地址来源时仍然让用户填。

写测试时踩到一个坑：`loadRuntimeConfig()` 的 promise 是**模块级缓存**，
跨用例会串味（前一个用例把结果定死成 null）→ 现在用例里显式
`resetRuntimeConfigCache()`（这个导出本来就是为此存在的）。
