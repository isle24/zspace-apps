# 「层叠聚焦」失败：坏的是尺子，不是窗口

## 症状

`verify.sh --live` 里窗口交互巡检报：

```
✗ 层叠聚焦   ["文件管理窗口:6","相册窗口:8"]
```

看着像"点下层窗口，它没有提到最前"。我先按回归处理（自己的窗口几何改动刚上线），
但**越查越不对**：应用侧的逻辑是对的。

## 定位：给检查加上"命中了谁"

原来这一项只报 z-index。补上诊断后一次就看清：

```
✗ 层叠聚焦  点击(495,90) 命中 window-titlebar
  文件管理窗口:6@455,82 | 相册窗口:8:focused@383,82
```

点击点 (495,90) **确实命中了 titlebar** —— 但那是 **相册**（在上层，z=8）的标题栏，
不是被测的 文件管理（在下层，z=6）。两个窗口：
文件管理被前面的**拖动**步骤移到了 **455**，相册在 **383**，于是**重叠**，
相册盖住了那个点。

**所以点击落在了上层窗口上**：相册保持聚焦（它本来就是），文件管理自然没被提到最前。
应用没坏 —— **是检查自己点错了地方**。

## 修法（改检查，不改应用）

1. **先验证命中再点**：用 `elementFromPoint` 逐个候选点（标题栏左 / 标题栏右 /
   窗口左下）确认属于目标窗口，才用它；一个都不行就明确提示"可能被完全盖住"。
2. **诊断信息保留**：以后这一项会同时报出命中元素、各窗口的 z 与坐标 ——
   上一次就是信息不够，才在应用侧白查半天。

修完：

```
✓ 层叠聚焦  点击(495,747) 命中 sidebar-bottom | 文件管理窗口:8:focused@455,82 | 相册窗口:7@383,82
全部通过
```
