# 值守：盯着商店引擎什么时候启用

## 为什么单独盯这一条

商店引擎是**唯一会由别人（Codex / 你）改变状态**、且改变之后**客户端行为会随之变化**的依赖：

- 现在：`engineMode: disabled`、`nasAuth.enabled: false` → 客户端如实显示"尚未启用" ✓ 行为正确；
- 启用后：`nasAuth.enabled: true` → 客户端会**立刻开始校验** `origin` 与 `storeId`，
  任一条不满足就拒绝绑定（按契约设计）。

也就是说：**引擎启用的那一刻，配置是否合规就从"无所谓"变成"必须对"** ——
而那时出错的表现是"客户端连不上商店"，很容易被当成客户端 bug。

## 已经做的两件事

### 1. 冒烟测试会在启用后强制校验

`scripts/deploy-smoke.mjs` 里第 7 项原本只如实报告状态。现在：

```
✓ 商店网关        引擎=disabled，NAS 管理员登录=未启用
  （引擎未启用，暂不校验 origin/storeId；启用后这里会强制检查）
```

一旦 `enabled` 变成 true，它会额外检查两条**并判失败**：

| 检查 | 要求 |
| --- | --- |
| `origin` | 必须是合法的 `http(s)://host[:port]`，且要等于客户端登录用的 NAS 地址 |
| `storeId` | 必须是 48 位小写十六进制 |

（`origin` 目前是**空串** —— 启用时最容易漏的就是这一条。）

### 2. 每 30 分钟自动盯一次

建了一条定时提醒（会话内），每 30 分钟检查：

1. 商店 `nasAuth.enabled` 是否变成 true → 变了就按契约核对并跑接入验证；
2. 页面是否不再是登录页（你登录了）→ 立刻跑 `verify.sh --live` 并汇报；
3. 都没变就回一句"值守无变化"，**不做别的改动**。

## 为什么值得写进文档

这是这个项目里第一次出现**"外部状态变化 → 我方行为变化"**的依赖。
前面几轮的经验（部署漂移、Mac 包滞后、lockfile 缺项）都是"我方产物之间的漂移" ✓
这一条是**别人改了之后我才需要动** ✓ 所以它需要的是**定时检查**，而不是提交时的检查。
