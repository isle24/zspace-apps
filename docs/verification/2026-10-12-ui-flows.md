# 两条不用登录也能验的界面流程

值守期间发现：有些**用户真实会走的路径**，我以前只有单测覆盖，没在真实引擎里跑过。
它们不需要 NAS 会话 —— 因为验的正是"连不上时怎么办"。

脚本：`scripts/ui-flows-check.cjs`（自给自足：拷 dist、写测试配置、起本地静态服务、
用 WebKit 跑完就关）。已接入 `verify.sh --all`。

## 1. 登录失败路径

填一个连不上的地址提交，必须：

| 检查 | 结果 |
| --- | --- |
| 留在登录页 | ✓ 没有假装登录成功（**没有出现桌面**） |
| 给出中文原因 | ✓「无法直接连接 NAS，请检查地址、网络与浏览器跨域条件」 |
| 按钮不卡死 | ✓ 从「正在连接…」恢复为「登录」 |
| 页面无可疑文本 | ✓ 无 `undefined` / `NaN` / `[object Object]` |
| 无脚本异常 | ✓ 0（唯一的 console 错误是那条网络请求失败本身） |

## 2. 独立商店页（Codex 的组件）

在 Mac 客户端同款引擎里加载 `store.html`：

| 检查 | 结果 |
| --- | --- |
| 组件渲染 | ✓ 标题「空间应用商店」、导航「发现/已安装/安装任务」、侧栏都在 |
| 网关缺失时 | ✓ 显示「暂时无法读取 / 商店服务返回无效数据（404）」+「重新读取」按钮 —— **不是空白、不是原始 JSON** |
| 无脚本异常 | ✓ 0 |

截图见本次提交说明；页面观感与文案都在。

## 顺手记两个坑

- 原始 `dist/` 里的商店页叫 **`store.html`**，只有部署时（`build.sh`）才改名 `shop.html` ——
  我第一版按 `shop.html` 去本地取，拿到的是 404 页，差点记成"商店页打不开"。
- 本地静态服务必须放一份 `runtime-config.json`（`nasOrigin` 留空 → 登录页才显示地址栏）。

## 意义

这三类检查（登录失败、商店页、以及上一轮的线上冒烟）**都不需要登录**，
却覆盖了用户真实会遇到的路径。之前"等登录"的这段时间里，
能验的东西其实比我想的多 —— **只是需要换个角度找**。

| --- | --- |

## 3. Mac 客户端的稳定性（值守顺带取证）

不用登录、也不用截图就能拿到的几条证据：

```
没有崩溃报告（~/Library/Logs/DiagnosticReports 里没有 Space Desktop）
进程在跑：Space Desktop（PID 15916）
内存：43 MB（启动 9 分钟后）
内置 sidecar：http://127.0.0.1:18435/health -> 200
```

也就是说：**应用开着、没崩、内存没有异常增长、自带服务仍在应答**。
这几条合起来能说明"打包产物至少不是一启动就坏"，但**说明不了界面观感** ——
那仍然只能靠眼睛。
