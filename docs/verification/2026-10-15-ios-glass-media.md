# 影视与音乐玻璃风格验收

## 结果

按用户确认的完整方案，影视、音乐和音乐播放条统一为 iPhone 应用风格。材质参考 [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：导航与控件使用磨砂材质，封面与正文保持清楚。

- 影视：全局海报背景、玻璃侧栏、胶囊工具组、影院深色画布、详情正文留白与内部滚动。
- 音乐：玫红强调、真实封面、紧凑曲库、专辑卡片、窄窗口横向导航。
- 播放器：悬浮玻璃条；歌词和队列分别占位，深浅色的文字、错误与关闭按钮保持可读。
- CSS 限定在影视、音乐与音乐播放器，不重做其它应用的样式或改变权限。

## 同时修复的实际问题

1. NAS 音乐时长以毫秒提供，旧列表按秒显示。真实音频 3:31 曾显示 3519:33，现列表与播放器一致。
2. 同一曲目封面 URL 刷新后仍保留旧失败状态。现在按会话、曲目、路径和封面身份重置。
3. 大曲库的“播放全部”实际只播放当前页。现在根据实际队列显示“播放本页”“播放结果”或完整集合的“播放全部”。
4. 音乐列表的通用行 ID 被误作歌曲、专辑或歌单 ID。现在优先使用明确的业务 ID；真实纯音乐的歌词不再串到其它歌曲。
5. 电影多个版本的 episode=0 被显示为第 0 集，并被生成虚构选集。现在显示“版本与文件”，只有真实正集数生成选集，花絮与无集数版本仍保留在文件和播放队列中。
6. 新音乐容器未命中旧播放器避让规则；已补齐留白。歌词与队列不再占用同一网格区域。
7. 551–700px 导航、浅色歌词和跳过按钮对比问题已通过独立审查发现并修复。
8. “全部影片”错误地把分页参数传入不支持分页的媒体库接口，导致读取失败。已修复参数传递、页面标题与返回首页状态，并按各媒体库最大页数计算分页，避免聚合列表末尾出现多余空页。

- 客户端 80 个测试文件、1323 项测试全部通过，typecheck 和生产构建通过；新增缺陷均先确认回归失败再修复。
- 独立代码审查覆盖媒体作用域、身份、分页、播放器和响应式规则，所提问题均已处理。
- 隔离 NAS UI 18455 使用真实官方接口，检查影院首页、媒体库与详情；音乐歌曲、专辑、封面与时长；暂停播放、歌词和队列；明暗主题及约 600px 窄窗口。
- 真实音频 metadata 与列表时长一致，实际目录和播放请求未被示例数据替换。测试播放已暂停并关闭。
- 影视详情的长文件列表可在内部滚动，普通电影不会显示伪造集数。
- r5 在隔离 NAS 上实际验证“全部影片”第 1、2 页，正式 18436 再次确认加载成功，返回媒体库恢复首页。
- 减少动态效果、高对比及无 backdrop-filter 的回退包含在实现中；本轮未切换操作系统无障碍设置逐项实测。
